# ふつうのダンジョン（仮）

一般的な不思議のダンジョンの試作。歩く・叩く・拾う・使う・満腹度という、ジャンルの普通の形を土台として作る。
再構築の工夫（歩数スキル・痕跡など）は今回は入れず、土台が立ってから1つずつ足して比べる。

- 遊ぶ場所： https://usouso.github.io/futsuu-dungeon/
- 設計の前提： `docs/理念.md`（守るもの）、`docs/試作仕様書.md`（今回の試作の仕様）
- 進め方：チケット（Issue）→ Claude が実装 → Codex がレビュー → 合格＋テスト全通過で取り込み
- 作業の報告： `REPORT.md`（やったこと／確かめたこと／未確認）

## 遊び方

`index.html` をブラウザで開く（ビルド不要）。5フロア潜って、最下層の階段に着いたらクリア。

- スマホ：方向ボタン（8方向＋待つ）、攻撃ボタン、持ち物の枠をタップ。
- PC：やじるし／テンキー／Q W E・A D・Z X C で移動、スペースで攻撃、S で待つ、1〜8（または I）で持ち物をえらぶ → Enter で使う／T で投げる／Esc でやめる。

### ボタン設定（キーコンフィグ）

「せってい」→「ボタン設定」で、キーボードのキーを変えられる。変えたいボタンをえらんでから、使いたいキーを押す。

- 変えられる操作：移動（8方向それぞれ）、待つ、こうげき、持ち物（えらぶ。押すたびに次の持ち物へ）、使う、投げる、やめる。
- 割り当てはブラウザに保存され、次に開いたときも同じ（localStorage）。
- 「はじめの キーに もどす」を2回押すと、既定値に戻る。
- キーが重なったとき：押したキーは、いまえらんだ操作のものになる（上書き）。前にそのキーを使っていた操作からは外れ、キーが1つも残らなければ「なし」と表示される。
- 割り当てを変えると、その操作のキーは押した1つだけになる（既定値では1つの操作に2〜3個のキーがある）。
- Tab・Shift などは割り当てられない。数字の 1〜8 は、別の操作に割り当てていなければ持ち物の番号えらびに使える。

### URL の切り替え

| 付けるもの | 意味 |
|---|---|
| `?seed=N` | 種を固定する（開いた直後の1回目が、毎回同じ地図 N になる） |
| `?auto=1` | 自動プレイ（最初から無音） |
| `?mute=1` | 最初から無音 |
| `?bg=1` | タイマーで進める（画面が裏にあっても進む） |

`?seed=N` の注意：

- 「もういちど」を押すと、次は N+1 の地図になる（その次は N+2 …）。同じ地図のくり返しで暗記にならないようにするため。
- **同じ N の地図をもう一度遊ぶには、ページを再読込する。**
- いま遊んでいる地図の seed は、「せってい」と結果の画面の下に出ている。

## ファイル

| ファイル | 役割 |
|---|---|
| `sim.js` | ルール。1手ごとに「何が起きたか」の記録を返す。画面を知らない。 |
| `ui.js` | 画面。ルールの記録を再生するだけ。 |
| `audio.js` | 短い合成音。 |
| `keys.js` | ボタン設定（キーコンフィグ）の決まり。どのキーがどの操作かの表。画面を知らない。 |
| `bots.js` | ボット4種と集計。 |
| `tests.js` | 仕様書の数値が文面どおりかのテスト。ボタン設定の決まりのテストもここ。 |
| `tools/shots.py` | スクリーンショットと、文字の重なり・はみ出し検査。ボタン設定を実際に押して確かめる場面もここ。 |

## 確かめ方

```
node tests.js                                   # ルールのテスト
node bots.js 500                                # ボット4種 × 500回
~/workspace/.venv-pw/bin/python tools/shots.py  # スクリーンショットと文字の検査（screenshots/ に保存）
```

状態：試作の1回目を実装し、レビューの修正依頼（1回目）に対応して再レビュー待ち（Issue #1／PR #2）。
